# Docker Installation

Docker installation provides the most consistent and isolated deployment experience for OpenClaw. This guide covers both automated and manual setup methods.

## Prerequisites

Before you begin, verify you have the required software:

| Requirement | Minimum Version | Verification Command |
|-------------|-----------------|---------------------|
| Docker | 24.0+ | `docker --version` |
| Docker Compose | v2.20+ | `docker compose version` |
| Disk Space | 2GB free | `df -h` |
| Memory | 512MB available | `free -m` |

![Docker Deployment Architecture](/openclaw/diagrams/docker-deployment-architecture.svg)

The diagram above shows the Docker deployment architecture including container orchestration, volume mounts, port mappings, and connections to external services.

## Automated Setup (Recommended)

The fastest way to get started:

```bash
# Clone the repository
git clone https://github.com/openclaw/openclaw.git
cd openclaw

# Run the automated setup
bash ./docker-setup.sh
```

**What the script does:**
1. Validates Docker and Docker Compose installation
2. Creates configuration directories (`~/.openclaw`, `~/.openclaw/workspace`)
3. Generates a secure 64-character gateway token
4. Builds the Docker image with all dependencies
5. Runs interactive onboarding wizard
6. Starts the gateway service

## Manual Installation

For more control over the installation process:

### Step 1: Create Directory Structure

```bash
mkdir -p ~/.openclaw/workspace
```

### Step 2: Generate Gateway Token

<Tabs items={['OpenSSL', 'Python', 'Node.js']}>
  <Tab value="OpenSSL">
    ```bash
    export OPENCLAW_GATEWAY_TOKEN=$(openssl rand -hex 32)
    echo "Gateway Token: $OPENCLAW_GATEWAY_TOKEN"
    ```
  </Tab>
  <Tab value="Python">
    ```bash
    export OPENCLAW_GATEWAY_TOKEN=$(python3 -c "import secrets; print(secrets.token_hex(32))")
    echo "Gateway Token: $OPENCLAW_GATEWAY_TOKEN"
    ```
  </Tab>
  <Tab value="Node.js">
    ```bash
    export OPENCLAW_GATEWAY_TOKEN=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
    echo "Gateway Token: $OPENCLAW_GATEWAY_TOKEN"
    ```
  </Tab>
</Tabs>

<Callout title="Security Note" type="warn">
  Keep your gateway token secure. Anyone with this token can access your OpenClaw gateway. Never commit it to version control.
</Callout>

### Step 3: Create Environment File

```bash
cat > .env << EOF
OPENCLAW_CONFIG_DIR=$HOME/.openclaw
OPENCLAW_WORKSPACE_DIR=$HOME/.openclaw/workspace
OPENCLAW_GATEWAY_PORT=18789
OPENCLAW_BRIDGE_PORT=18790
OPENCLAW_GATEWAY_BIND=lan
OPENCLAW_GATEWAY_TOKEN=$OPENCLAW_GATEWAY_TOKEN
OPENCLAW_IMAGE=openclaw:local
EOF
```

### Step 4: Build Docker Image

```bash
docker build -t openclaw:local .
```

### Step 5: Start Services

```bash
# Start gateway in background
docker compose up -d openclaw-gateway

# Verify startup (watch logs)
docker compose logs -f openclaw-gateway
```

## Docker Compose Configuration

The `docker-compose.yml` defines two services:

```yaml
services:
  openclaw-gateway:
    image: ${OPENCLAW_IMAGE:-openclaw:local}
    environment:
      HOME: /home/node
      TERM: xterm-256color
      OPENCLAW_GATEWAY_TOKEN: ${OPENCLAW_GATEWAY_TOKEN}
    volumes:
      - ${OPENCLAW_CONFIG_DIR}:/home/node/.openclaw
      - ${OPENCLAW_WORKSPACE_DIR}:/home/node/.openclaw/workspace
    ports:
      - "${OPENCLAW_GATEWAY_PORT:-18789}:18789"
      - "${OPENCLAW_BRIDGE_PORT:-18790}:18790"
    init: true
    restart: unless-stopped
    command: ["node", "dist/index.js", "gateway", "--bind", "${OPENCLAW_GATEWAY_BIND:-lan}"]

  openclaw-cli:
    image: ${OPENCLAW_IMAGE:-openclaw:local}
    volumes:
      - ${OPENCLAW_CONFIG_DIR}:/home/node/.openclaw
      - ${OPENCLAW_WORKSPACE_DIR}:/home/node/.openclaw/workspace
    stdin_open: true
    tty: true
    entrypoint: ["node", "dist/index.js"]
```

## Commands Reference

| Operation | Command |
|-----------|---------|
| Start gateway | `docker compose up -d openclaw-gateway` |
| Stop gateway | `docker compose down` |
| View logs | `docker compose logs -f openclaw-gateway` |
| Restart gateway | `docker compose restart openclaw-gateway` |
| Run CLI commands | `docker compose run --rm openclaw-cli <command>` |
| Health check | `docker compose run --rm openclaw-cli health --token "$OPENCLAW_GATEWAY_TOKEN"` |
| Enter container shell | `docker compose exec openclaw-gateway bash` |
| Rebuild image | `docker compose build --no-cache` |

## Volume Mounts

| Host Path | Container Path | Purpose |
|-----------|----------------|---------|
| `~/.openclaw` | `/home/node/.openclaw` | Configuration and state |
| `~/.openclaw/workspace` | `/home/node/.openclaw/workspace` | Agent workspace files |

## Port Configuration

| Port | Protocol | Purpose |
|------|----------|---------|
| **18789** | WebSocket/HTTP | Gateway control plane + Control UI |
| **18790** | TCP | Bridge protocol (legacy) |
| **18793** | HTTP | Canvas file server |

## Verification

After starting the gateway, verify the installation:

```bash
# Check gateway health
docker compose run --rm openclaw-cli health --token "$OPENCLAW_GATEWAY_TOKEN"

# Access Control UI
# Open: http://127.0.0.1:18789?token=<your-token>
```

**Expected log signals:**

## Fixing Control UI Access

### Problem: "pairing required" Error

When accessing `http://localhost:18789`, you may see:
```
disconnected (1008): pairing required
```

This happens because Docker's internal network (`172.18.0.1`) is not recognized as localhost.

### Solution: Update openclaw.json

Add Control UI bypass settings to your configuration:

```json
{
  "gateway": {
    "port": 18789,
    "auth": {
      "mode": "token",
      "token": "YOUR_GATEWAY_TOKEN"
    },
    "controlUi": {
      "allowInsecureAuth": true,
      "dangerouslyDisableDeviceAuth": true
    }
  }
}
```

**Key settings:**
- `controlUi.allowInsecureAuth: true` - Allows token-only auth
- `controlUi.dangerouslyDisableDeviceAuth: true` - Disables device identity checks for Docker

<Callout title="Security Note" type="warn">
  These settings bypass device authentication. Only use in development or trusted environments.
</Callout>

## Useful Docker Commands

### Container Management

```bash
# Start gateway
docker compose up openclaw-gateway

# Start in background
docker compose up -d openclaw-gateway

# Stop all services
docker compose down

# Restart gateway
docker compose restart openclaw-gateway

# View logs
docker logs openclaw-openclaw-gateway-1 --tail 50

# Follow logs in real-time
docker logs -f openclaw-openclaw-gateway-1

# Enter container shell
docker exec -it openclaw-openclaw-gateway-1 /bin/sh
```

### CLI Commands

```bash
# Check status
docker compose run --rm openclaw-cli status

# Run diagnostics
docker compose run --rm openclaw-cli doctor

# List available models
docker compose run --rm openclaw-cli models list

# Send a test message
docker compose run --rm openclaw-cli agent --message "Hello"

# Run onboarding wizard
docker compose run --rm openclaw-cli onboard
```

## Troubleshooting

| Issue | Symptom | Solution |
|-------|---------|----------|
| Port already in use | "Address already in use" error | Change `OPENCLAW_GATEWAY_PORT` in `.env` |
| Permission denied | Container fails to start | Ensure Docker daemon is running, user is in docker group |
| Build fails | Build errors | Run `docker compose build --no-cache` to rebuild cleanly |
| Token mismatch | Authentication failing | Verify `OPENCLAW_GATEWAY_TOKEN` is set in `.env` and config |
| Gateway token missing | "unauthorized: gateway token missing" | Add `?token=YOUR_TOKEN` to URL |
| Pairing required | "disconnected (1008): pairing required" | Add `controlUi.dangerouslyDisableDeviceAuth: true` |
| CLI can't connect | "gateway closed (1006)" | Edit config files directly instead of using CLI |
| Invalid auth mode | "gateway.auth.mode: Invalid input" | Only use "token" or "password", not "none" |

### Key Learnings

1. **Docker networking quirk**: Browser connections through Docker appear as remote (172.18.0.1) not local (127.0.0.1), triggering pairing requirements.

2. **Valid auth modes**: Only `"token"` or `"password"` - there is no way to disable auth completely.

3. **Config changes require restart**: Always run `docker compose restart openclaw-gateway` after editing openclaw.json.

4. **CLI limitations in Docker**: The CLI container can't reach the gateway due to Docker networking isolation. Edit config files directly on the mounted volume instead.
